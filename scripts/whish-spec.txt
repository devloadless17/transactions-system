Overview  
The Whish API is a REST based service accessible over HTTPS. It supports JSON formatted requests 
and responses and is intended to be consumed by authorized distributors. 
Environments 
Production 
URL: https://api.whish.money/itel-service/api 
Sandbox 
URL: https://api.sandbox.whish.money/itel-service/api 
Communication Requirements 
Protocol and Format 
• The distributor must be capable of producing and consuming JSON over HTTPS.  
• All requests and responses use the application/json format. 
Request Headers 
All requests sent to Whish services must include the following HTTP headers.  
Header 
Name Description 
channel Value provided by Whish 
secret Value provided by Whish 
websiteUrl URL of the third party website or application name where the API is integrated 
User-Agent Identifies the consuming website or application 
 
User-Agent format: “Whish/1.0 (https://whish.money; support@whish.money)" 
Response Structure 
All API responses follow a unified structure with the attributes listed below.  
Attribute Description 
status Boolean value indicating success or failure 
code Operation-specific failure code 
dialog Contains an optional title and message to be displayed to the user 
data Contains the response payload based on the executed operation 
Notes 
• Missing or invalid headers may result in request rejection. 
• The User-Agent header is required for monitoring, analytics, and support purposes.

Get Balance 
This method returns the real balance of the account. 
You can specify the currency (LBP or USD) using “?currency=LBP” or “?currency=USD”. 
Voided items are items which are sold and not used for some reason, so they are put on hold for later 
usages. 
URI  
LBP: GET /payment/account/balance?currency=LBP  
USD: GET /payment/account/balance?currency=USD  
Request 
No request body attributes are needed; just include the required headers and specify the currency (LBP or 
USD) in the query. 
Response Data 
Field   Description  Type  
balanceDetails   Complex Type 
      balance  The real balance of the account.  Double 
Response Example  
Successful Response:  
USD:                                                                                   LBP: 
{ 
    "status": true, 
    "code": null, 
    "dialog": null, 
    "actions": null, 
    "extra": null, 
    "data": { 
        "balance": 10439.0 
    } 
} 
 
{ 
    "status": true, 
    "code": null, 
    "dialog": null, 
    "actions": null, 
    "extra": null, 
    "data": { 
        "balance": 943975.0 
    } 
}

Post Payment 
This method returns the URL, where the client will be redirected to pay for the merchant through WHISH 
Balance. 
URI 
POST /payment/whish 
Request 
Besides the header attributes which are mandatory in all requests, following are the attributes needed to 
be attached in the requests body: 
Field   Description  Type  
amount Amount to be paid by client Double 
currency The amount’s currency. Supported currencies: LBP/USD String 
invoice Details/Description about the payment String  
externalId ID provided by third party Long  
successCallbackUrl GET Callback URL provided by third party for successful transaction String 
failureCallbackUrl GET Callback URL provided by third party for failed transaction String 
successRedirectUrl GET Redirect URL provided by third party for successful transaction String 
failureRedirectUrl GET Redirect URL provided by third party for failed transaction String 
 
Test Cases: 
• Success: Use the phone number 96170902894 on the payment page with the OTP 111111.  
• Failure: Use any phone number with an OTP other than 111111. 
Notes 
• The callback and redirect URLs are fully specified by the third party integrating with Whish.  
===== PAGE 7 =====
  
 
• Callback URLs are triggered by Whish using a GET request to notify the third party of the 
transaction result. 
• Redirect URLs are used to redirect the client after the payment flow is completed.  
• The third party may append any custom query parameters to the callback or redirect URLs, such 
as a unique identifier, timestamp, order reference, or any other tracking information.  
• Whish will call or redirect to the provided URLs as received, without altering the query 
parameters. 
• externalId must be a numeric value generated by the third party and must be unique per request, 
serving as the reference identifier for the transaction. 
• No OTP is delivered in sandbox environment. 
Request Sample:  
 
{  
"amount": "1",  
"currency": "USD",  
"invoice": "Order #1",  
"externalId": 1,  
"successCallbackUrl": "https://example.com/api/payment/success",  
"failureCallbackUrl": "https://example.com/api/payment/failure",  
"successRedirectUrl": "https://example.com/thank-you",  
"failureRedirectUrl": "https://example.com/payment-error"  
}  
 
Response Data 
Field  Description  Type  
collectUrl The payment page URL  String

currency The amount currency. Supported currencies: “LBP, “USD” String 
externalId ID provided by third party Long
