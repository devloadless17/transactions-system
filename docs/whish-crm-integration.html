Whish Pay — CRM Integration Guide

How a company connects its CRM to generate Whish payment links and reconcile them to transactions.

BASE URL
https://api.yourplatform.com/v1
AUTH
Authorization: Bearer tsk_XXXXXXXX_…

Overview

Your CRM calls our API to generate a Whish payment link for a customer. You share the returned link, the customer pays on Whish's hosted page, and the payment settles automatically into your wallet (minus commission). Each payment carries a numeric reference (externalId) that you store against your own order/invoice so you can tie the payment back to the right record.

Flow at a glance

Step 1 — Get a company API key

A one-time setup. The key authenticates your CRM (server-to-server). Two ways to obtain it:

  • Self-serve: the company owner signs in to the dashboard → Settings → API keys → Create key.
  • Via platform admin: an admin issues one for you under /admin/companies/<id>/api-keys.
The plaintext key (tsk_XXXXXXXX_…) is shown once at creation. Store it as a secret in your CRM. Treat it like a password — anyone with it can create payment links for your company.

Step 2 — Create a payment link

POST /v1/integrations/whish/payments

# request
curl -X POST https://api.yourplatform.com/v1/integrations/whish/payments \
  -H "Authorization: Bearer tsk_XXXXXXXX_your_secret" \
  -H "Content-Type: application/json" \
  -d '{
        "amount": "25.00",
        "currency": "USD",        // USD or LBP
        "invoice": "Order #4821"   // your description, shown to the payer
      }'
# response 201
{
  "id": "dac86656-8641-42be-bb39-aaa7eddedc2d",
  "externalId": "3",                // ← THE REFERENCE: store this against your order
  "status": "PENDING",
  "amount": "25.00",
  "currency": "USD",
  "invoice": "Order #4821",
  "collectUrl": "https://whish.money/pay/8nQS2mL",   // ← send this to your customer
  "transactionId": null,
  "createdAt": "2026-05-31T10:00:00.000Z"
}

Save externalId on your order. Redirect/send the customer to collectUrl.

Same call, other languages

Authentication is identical everywhere: Authorization: Bearer <company key>.

Python (requests)

import os, requests
BASE, KEY = "https://api.yourplatform.com/v1", os.environ["WHISH_KEY"]
H = {"Authorization": f"Bearer {KEY}"}

data = requests.post(f"{BASE}/integrations/whish/payments", headers=H,
    json={"amount": "25.00", "currency": "USD", "invoice": "Order #4821"}).json()
print(data["collectUrl"], data["externalId"])           # share / store
status = requests.get(f"{BASE}/integrations/whish/payments/{data['externalId']}", headers=H).json()
print(status["status"])                                  # PENDING | PAID | FAILED

Node.js (fetch)

const BASE = "https://api.yourplatform.com/v1", KEY = process.env.WHISH_KEY;
const auth = { Authorization: `Bearer ${KEY}`, "Content-Type": "application/json" };
const data = await (await fetch(`${BASE}/integrations/whish/payments`, {
  method: "POST", headers: auth,
  body: JSON.stringify({ amount: "25.00", currency: "USD", invoice: "Order #4821" }),
})).json();
console.log(data.collectUrl, data.externalId);

.NET (C#)

using System.Net.Http.Headers;
using System.Net.Http.Json;
var http = new HttpClient { BaseAddress = new Uri("https://api.yourplatform.com/v1/") };
http.DefaultRequestHeaders.Authorization =
    new AuthenticationHeaderValue("Bearer", Environment.GetEnvironmentVariable("WHISH_KEY"));
var resp = await http.PostAsJsonAsync("integrations/whish/payments",
    new { amount = "25.00", currency = "USD", invoice = "Order #4821" });
resp.EnsureSuccessStatusCode();
var data = await resp.Content.ReadFromJsonAsync<JsonElement>();
Console.WriteLine(data.GetProperty("collectUrl").GetString());

Step 3 — Customer pays

The customer completes payment on the Whish-hosted page. When done, Whish redirects their browser to a thank-you / error page and (separately) notifies our server. You don't have to do anything here. Settlement is automatic: on confirmed success we apply your commission rules, write the double-entry ledger, and credit your wallet — the payment's status becomes PAID and transactionId is filled in.

Step 4 — Know the result

Pick whichever fits your CRM:

A. Poll by reference (simplest)

GET /v1/integrations/whish/payments/{externalId}

curl https://api.yourplatform.com/v1/integrations/whish/payments/3 \
  -H "Authorization: Bearer tsk_XXXXXXXX_your_secret"

# → { "externalId":"3", "status":"PAID", "payerPhoneNumber":"961…",
#     "transactionId":"…", "paidAt":"…" }

Poll every ~30–60s while status is PENDING. Terminal states: PAID, FAILED, EXPIRED.

If a callback was missed, force a fresh pull from Whish: POST /v1/integrations/whish/payments/{externalId}/refresh

B. Customer-facing redirect (optional UX)

After paying, the customer's browser lands on a success or error page carrying ?ref={externalId}. Use these to show your own confirmation screen.

Webhooks (optional — push instead of poll)

Instead of polling, set a webhook URL (dashboard → Developers, or your platform admin). On a confirmed payment we POST a signed event to your URL: 

# headers
X-Whish-Event: whish.payment.paid
X-Whish-Signature: sha256=<hex hmac of the raw body, keyed with your webhook secret>

# body
{
  "event": "whish.payment.paid",
  "data": {
    "externalId": "3", "status": "PAID",
    "amount": "25.00", "currency": "USD",
    "payerPhoneNumber": "961…", "transactionId": "…", "paidAt": "…"
  }
}
Always verify the signature: compute HMAC-SHA256(secret, rawBody) and compare to the X-Whish-Signature header before trusting the event. Delivery is best-effort — keep polling as a fallback.

Endpoint reference

MethodPathPurpose
POST/integrations/whish/paymentsCreate a payment link
GET/integrations/whish/payments/{ref}Get a payment by reference
POST/integrations/whish/payments/{ref}/refreshForce-reconcile status with Whish

All require Authorization: Bearer <company key>. No CSRF, no cookies. {ref} is the numeric externalId.

Request fields

FieldTypeNotes
amountstringDecimal string, e.g. "25.00". Must be > 0.
currencystringUSD or LBP (Whish supports these two).
invoicestring1–200 chars. Description shown to the payer.

Status values

StatusMeaning
PENDINGLink created; payer hasn't completed payment.
PAIDConfirmed; wallet credited, transactionId set.
FAILEDWhish reported failure (or link creation failed).
EXPIREDNever paid; closed out during reconciliation.

Errors

Errors use a consistent shape:

{ "error": { "code": "VALIDATION_ERROR", "message": "amount must be positive" } }
HTTPcodeWhen
401UNAUTHORIZEDMissing / invalid / revoked API key.
400VALIDATION_ERRORBad body (amount, currency, invoice) or bad reference.
404NOT_FOUNDReference not found for your company.
502WHISH_ERRORWhish was unreachable or rejected the request.

Sandbox testing

Against the sandbox, complete a payment with:

Phone 96170902894  ·  OTP 111111  →  success.
Any other OTP → failure. (No OTP SMS is sent in sandbox.)

Reference is idempotent. The numeric externalId is unique per payment. Our settlement is keyed on it, so even if Whish notifies us twice, your wallet is credited exactly once.
